# Phase 1b — Web App (Owner Panel + Company Admin) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Arabic (RTL) Next.js web app on top of the Phase 1a database: phone-OTP login, company self-registration, invitation acceptance, the company workspace (structure tree, positions, invitations, employees, announcements, notifications) and the platform owner panel (companies, subscriptions, plans, department catalog).

**Architecture:** `apps/web` is a Next.js App Router app that talks to Supabase directly with the user's session (`@supabase/ssr`); every rule is already enforced by RLS/RPCs from Phase 1a, so the web layer only validates input (shared Zod schemas), hides what the user cannot do (shared `hasPermission`), and maps `ORG_*` error codes to Arabic. Pure logic (tree building, route decisions, UI gating, formatting) lives in small tested modules under `apps/web/src/lib`; pages stay thin.

**Tech Stack:** Next.js 15 (App Router, Server Actions), React 19, TypeScript strict, Tailwind CSS 4, `@supabase/ssr` + `@supabase/supabase-js` v2, Vitest + Testing Library (jsdom), `@orgbu/shared`.

**Spec:** `docs/superpowers/specs/2026-11-09-company-management-platform-design.md` (§2.1, §3.1, §4.1–4.4, §4.6, §5.4, §8, §10 Phase 1). Builds on `docs/superpowers/plans/2026-11-09-phase1a-foundation.md` (schema, RPC names, error codes).

**Out of scope:** mobile app (Phase 1c), desktop wrapper (Phase 4), payment gateway (Phase 4), production hosting (decided at the end of this plan with the owner).

## Global Constraints

- UI language Arabic, `<html lang="ar" dir="rtl">`; all user-facing errors come from `messageFor(code)` in `@orgbu/shared`.
- Login is phone + OTP only (`supabase.auth.signInWithOtp({ phone })` / `verifyOtp({ phone, token, type: 'sms' })`); phone always passed through `normalizeSaudiPhone` first.
- No business rule is enforced only in the browser: every write goes through RLS-protected tables or Phase 1a RPCs.
- Supabase project ref `ziwyfxslsmzqddirbnod`; env vars `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` in `apps/web/.env.local` (never committed).
- Full identity numbers are shown only after an explicit "إظهار" click calling `get_employee_identity_number`; lists show `•••• ` + `identity_last4`.
- Invitation link format: `${origin}/invite/${token}`; token is shown once, right after creation.
- Commit messages end with the session attribution lines.

## Review Focus

1. User whose OTP session exists but who has no employee row and is not a platform admin opens `/app/...` → redirected to `/onboarding`, never a blank page (Task 3 test `routeFor` "authenticated without employee").
2. Database returns an error that is not an `ORG_*` code (network, RLS text) → user sees the generic Arabic message, not raw English SQL (Task 2 test "non-ORG error").
3. Org tree data that is momentarily inconsistent (a unit whose parent was just deleted by someone else) → tree still renders, orphan shown under the root, no crash (Task 6 test "orphan unit").
4. HR (no `roles.manage`) opens the new-position form → company-admin role is not offered (Task 7 test `assignableRoles`), matching DB rule from 0010.
5. Phone typed in Arabic-Indic digits (`٠٥٥١٢٣٤٥٦٧`) → accepted and normalized (Task 3 test "arabic digits").
