# منصة إدارة الشركات (org BU): وثيقة التصميم

- **التاريخ:** 2026-11-09
- **صاحب المنصة:** محمود مصطفى هاجر
- **الحالة:** مسودة للمراجعة

---

## 1. الهدف

منصة اشتراكات (SaaS) تشترك فيها الشركات لإدارة هيكلها وموظفيها وشغلها اليومي. المنصة تشتغل على الويب والديسكتوب وأندرويد وiOS.

- **صاحب المنصة** يدير الشركات المشتركة والباقات والأسعار وتذاكر الدعم من لوحة خاصة بيه.
- **الشركة المشتركة** تبني هيكلها (فروع، إدارات، أقسام) وتدعو موظفيها وتديرهم: الحضور، والطلبات، والمهام، والاجتماعات، والإجازات، والرواتب، والعقود، والإقامات.
- **النظام يناسب الأنشطة التجارية والخدمية والمختلطة** من خلال نموذج هيكل مرن واحد.

### معايير النجاح

1. شركة جديدة تقدر تسجل وتبني هيكلها وتدعو أول موظف في أقل من 15 دقيقة.
2. كل موظف يتعرف مديره المباشر تلقائيًا من الهيكل، من غير ما حد يدخله يدويًا.
3. مفيش شركة تقدر تشوف بيانات شركة تانية، والقاعدة دي مطبقة على مستوى قاعدة البيانات.
4. نفس البيانات بتظهر لحظيًا على كل المنصات.

## 2. المكونات الرئيسية

```
لوحة صاحب المنصة
   └── مساحة الشركة المشتركة
         ├── الوحدات: الحضور | المهام | الاجتماعات | الإجازات والرواتب والسلف
         │            العقود والإقامات | الأخبار والقرارات | تذاكر الدعم
         └── الأساس المشترك: الهيكل والفروع | الموظفين | الصلاحيات | محرك الطلبات | الإشعارات
```

### 2.1 لوحة صاحب المنصة
- قائمة الشركات المشتركة وحالة اشتراك كل شركة: تجريبي، نشط، منتهي، ملغي.
- إدارة الباقات: الاسم، والسعر الشهري والسنوي، والحد الأقصى للموظفين، والوحدات المتاحة في كل باقة.
- إدارة قائمة الإدارات الجاهزة اللي الشركات بتختار منها، مع تحديد الإدارات الثابتة.
- استقبال تذاكر الدعم والرد عليها.

### 2.2 الأساس المشترك
الهيكل، والموظفين، والصلاحيات، ومحرك الطلبات، والإشعارات. مشروح بالتفصيل في القسم 4.

### 2.3 الوحدات
| الوحدة | الوصف المختصر |
|---|---|
| الحضور والانصراف | تسجيل يومي، وقواعد خصم تحددها الشركة، وأعذار تمر على محرك الطلبات |
| إسناد المهام | المدير يسند مهام للي تحته، والمدة محددة أو مفتوحة، واللي أسند المهمة بس هو اللي يلغي المدة |
| الاجتماعات | دعوة أشخاص أو وحدات، والحضور إلزامي أو اختياري، وقبول أو اعتذار، وزرار إضافة للتقويم، وتذكير |
| الأخبار والقرارات | نشر لجمهور محدد (الشركة كلها، أو فرع، أو إدارة) مع إشعار |
| العقود والإقامات | حساب انتهاء العقد والإقامة ومهلة المستقدم، وتنبيه قبلها بمدة تحددها الشركة |
| الإجازات والرواتب والسلف | أرصدة وطلبات إجازة، ورواتب بالخصومات، وطلب سلفة يمر على محرك الطلبات |
| تذاكر الدعم | موظف أو مدير الشركة يفتح تذكرة، وصاحب المنصة يتابعها لحد ما تتحل |

## 3. المنصات والتقنية

### 3.1 توزيع الاستخدام
- **الويب:** الشغل الإداري (الهيكل، والصلاحيات، والرواتب، والتقارير)، ولوحة صاحب المنصة.
- **الديسكتوب:** نفس تطبيق الويب ملفوف كبرنامج، ومعاه إشعارات على الجهاز وربط مع أجهزة البصمة. هيتبني بعد المرحلة 1.
- **الموبايل (أندرويد وiOS):** الشغل اليومي: التسجيل من رابط الدعوة، والحضور بالموقع، والطلبات، والموافقات، والمهام، والاجتماعات، والإشعارات الفورية.

| الوظيفة | ويب | ديسكتوب | موبايل |
|---|---|---|---|
| لوحة صاحب المنصة | ✓ | ✓ | – |
| إعداد الهيكل والصلاحيات | ✓ | ✓ | – |
| إدارة الموظفين | ✓ | ✓ | عرض |
| التسجيل من رابط الدعوة | ✓ | – | ✓ |
| الحضور والانصراف | – | أجهزة البصمة | ✓ بالموقع/QR |
| الطلبات والموافقات، المهام، الاجتماعات، الأخبار | ✓ | ✓ | ✓ |
| الرواتب والتقارير | ✓ | ✓ | الموظف يشوف راتبه |

### 3.2 التقنية المقترحة
| الطبقة | الاختيار | السبب |
|---|---|---|
| الويب | Next.js + TypeScript، والواجهة بالعربي (RTL) مع دعم الإنجليزي | قوي في الشاشات الإدارية والجداول |
| الديسكتوب | Tauri، بيلف تطبيق الويب | خفيف، وبيسمح بالوصول للأجهزة المحلية |
| الموبايل | React Native (Expo) + TypeScript | تطبيق واحد لأندرويد وiOS، وبيشارك الأنواع ومنطق الشغل مع الويب |
| السيرفر وقاعدة البيانات | Supabase (PostgreSQL + Auth + Storage + Edge Functions) | عزل الشركات عن بعض بسياسات RLS، ودخول بكود OTP على الجوال، وإشعارات لحظية |
| تنظيم الكود | Monorepo (Turborepo): `apps/web`، `apps/mobile`، `apps/desktop`، `packages/shared`، `supabase/` | كود مشترك واحد للأنواع والتحقق والصلاحيات |

## 4. الأساس المشترك (تفصيل)

### 4.1 نموذج الهيكل
الهيكل شجرة **وحدات تنظيمية** (`org_units`). كل وحدة ليها:
- **نوع:** `branch` (فرع)، أو `department` (إدارة)، أو `section` (قسم)، أو `team` (فريق).
- **أب** (`parent_id`)، والجذر هو الشركة نفسها (الإدارة العامة).
- **منصب مدير** (`manager_position_id`).

**قوالب حسب النشاط** (الشركة تختار نوع نشاطها وقت التسجيل):
- **تجاري:** الإدارة العامة ← فروع ← إدارات أو أقسام ← موظفين.
- **خدمي:** الإدارة العامة ← إدارات ← أقسام أو فرق ← موظفين.
- **مختلط:** الاتنين مع بعض.

القالب مجرد نقطة بداية، والشركة تقدر تعدّل فيه.

**حساب المدير المباشر:**
1. لو الموظف مش مدير وحدته، يبقى مديره المباشر هو مدير الوحدة.
2. لو الموظف هو مدير وحدته، أو الوحدة مالهاش مدير، النظام يطلع للوحدة اللي فوقها ويكرر الخطوات لحد ما يلاقي مدير.
3. المدير العام مديره المباشر هو المالك، أو مفيش.

**قواعد الإدارات:**
- **الإدارات الثابتة** (`is_fixed`)، وهي الإدارة العامة والموارد البشرية والمالية، بتتعمل تلقائيًا مع كل شركة. الإدارة الثابتة اللي عليها موظفين متتشالش غير لو اتحددت وحدة بديلة وانتقل ليها كل موظفينها، والانتقال بيحصل في خطوة واحدة.
- **الإدارات المتغيرة** الشركة بتختارها من قائمة صاحب المنصة، أو بتعمل إدارة جديدة باسم من عندها.
- **أي وحدة عليها موظفين أو تحتها وحدات** متتمسحش قبل ما الموظفين والوحدات اللي تحتها يتنقلوا.

### 4.2 المناصب والموظفين
- **المنصب** (`position`) بيتبع وحدة، وليه مسمى وظيفي ودور (`role`) ومعرّف بيقول هل هو منصب مدير ولا لأ.
- **الموظف** بيتربط بمنصب واحد في المرحلة 1.

**بيانات الموظف:**
| الحقل | ملاحظات |
|---|---|
| الاسم الكامل | إلزامي |
| تاريخ الميلاد | والسن بيتحسب منه |
| النوع | ذكر أو أنثى |
| الجنسية | لو "سعودي": نوع الهوية هوية وطنية |
| نوع الهوية | هوية وطنية، أو إقامة (مقيم)، أو رقم حدود (مستقدم جديد) |
| رقم الهوية أو الإقامة أو الحدود | **مشفر**، وبيظهر مخفي جزئيًا لغير المصرح لهم |
| تاريخ انتهاء الإقامة | إلزامي لو نوع الهوية "إقامة" |
| تاريخ الدخول | إلزامي لو نوع الهوية "رقم حدود"، ومنه بتتحسب مهلة استخراج الإقامة |
| رقم الجوال | فريد، وبيُستخدم للدخول بكود OTP |
| البريد الإلكتروني | فريد، وبديل للدخول |
| بداية العقد ونهايته | بيدخلهم الـHR، وبيتحسب منهم موعد انتهاء العقد |

### 4.3 تسجيل الشركة ودعوة الموظفين
1. مدير حساب الشركة يسجل حسابه: الجوال مع OTP، والإيميل.
2. يدخل بيانات الشركة: الاسم القانوني، ورقم السجل التجاري (فريد على المنصة)، وعدد الموظفين، ونوع النشاط.
3. يختار باقة، أو يبدأ فترة تجريبية.
4. النظام يعمل الهيكل من القالب المناسب ومعاه الإدارات الثابتة، ومدير الحساب يختار الإدارات المتغيرة أو يضيف إدارات جديدة.
5. يعمل المناصب جوه الوحدات.
6. لكل منصب فاضي يعمل **رابط دعوة**: لشخص واحد، ويستخدم مرة واحدة، وينتهي بعد 7 أيام (المدة دي قابلة للتعديل). الرابط بيتبعت بالإيميل أو الجوال أو بيتنسخ.
7. المرشح يفتح الرابط على الموبايل أو الويب، ويسجل بياناته، ويتحقق من جواله بكود OTP. بعدها بيتربط تلقائيًا بالمنصب والوحدة والمدير المباشر.
8. بعد كده بيدخل بالجوال مع OTP، أو بالإيميل وكلمة مرور.

### 4.4 الصلاحيات
كل صلاحية = **فعل** + **نطاق**.
- **النطاقات:** `company` (الشركة كلها)، و`branch` (فرعه)، و`unit` (وحدته وكل اللي تحتها)، و`self` (نفسه).
- **الأدوار الافتراضية** بتتعمل مع كل شركة، والشركة تقدر تعدّل فيها أو تضيف أدوار جديدة:

| الدور | أمثلة على الصلاحيات | النطاق الافتراضي |
|---|---|---|
| مدير حساب الشركة | كل الصلاحيات | company |
| الموارد البشرية | دعوة وتعيين، فسخ عقد، تعديل بيانات الموظفين، اعتماد الأعذار والإجازات | company |
| المالية | الرواتب، السلف، الخصومات | company |
| مدير فرع | إدارة موظفين الفرع، المهام، الموافقة على الطلبات، الاجتماعات | branch |
| مدير إدارة | المهام، الموافقة على طلبات فريقه، الاجتماعات | unit |
| موظف | تقديم الطلبات، عرض مهامه وراتبه وبياناته | self |

قائمة الصلاحيات معرّفة في الكود (`packages/shared`). قاعدة البيانات بتتحقق منها بسياسات RLS ودوال SQL، وواجهة المستخدم بتخفي الأزرار اللي الشخص مالوش صلاحية عليها.

### 4.5 محرك الطلبات
نموذج واحد لكل الطلبات: عذر تأخير، وعذر انصراف مبكر، وإجازة، وسلفة، وأي نوع يتضاف بعد كده.
- **مسار الطلب:** الموظف يقدّم الطلب ← يتوجه تلقائيًا للمسؤول عن نوعه (الشركة بتحدد لكل نوع: المدير المباشر، أو دور معين زي HR أو المالية) ← المسؤول ياخد قرار.
- **القرارات المتاحة:** موافقة، أو رفض (مع السبب)، أو تأجيل (بمهلة لتاريخ معين)، أو تحويل لشخص أو دور تاني.
- **الحالات:** `pending`، `approved`، `rejected`، `postponed`، `forwarded`، `cancelled`.
- كل خطوة بتتسجل في سجل الطلب ويوصل عنها إشعار.

**يتبني في المرحلة 2**، والمرحلة 1 بتجهز الجداول الأساسية بس.

### 4.6 الإشعارات
- إشعار داخل التطبيق، وإشعار فوري على الموبايل (Expo Push)، وإيميل اختياري.
- كل وحدة بتولّد الإشعارات بتاعتها من خلال خدمة واحدة.

## 5. تفاصيل الوحدات (للمراحل اللاحقة)

### 5.1 الحضور والانصراف (المرحلة 2)
- **طرق التسجيل:** من الموبايل بشرط يكون في نطاق موقع الفرع (GPS)، أو بمسح QR في الفرع، أو بربط مع أجهزة البصمة من الديسكتوب. الشركة تختار طريقة أو أكتر.
- **إعدادات الشركة:** مواعيد الدوام لكل وحدة أو فرع، ودقايق السماح، وقواعد الخصم على التأخير والانصراف المبكر.
- قواعد الخصم إعدادات بتحددها الشركة، ولازم تراجعها مع نظام العمل السعودي.
- **العذر:** الموظف يقدّم عذر، فيتعمل طلب في محرك الطلبات. لو اتقبل، الخصم يتلغي.

### 5.2 المهام (المرحلة 3)
- المدير يسند مهام للي تحته في الهيكل بس، حسب نطاق صلاحيته.
- المهمة فيها: عنوان، ووصف، ومرفقات، وتاريخ بداية، ومدة محددة أو "مفتوحة".
- اللي أسند المهمة بس هو اللي يلغي المدة أو يعدّلها.
- **حالات المهمة:** جديدة، وجاري التنفيذ، ومكتملة، ومتأخرة، وملغية.

### 5.3 الاجتماعات (المرحلة 3)
- الاجتماع فيه: عنوان، ووقت، ومدة، ومكان أو رابط أونلاين، وجدول أعمال، ومرفقات.
- **المدعوين:** أشخاص بالاسم أو وحدات كاملة، وكل واحد حضوره إلزامي أو اختياري.
- **الدعوة:** إشعار فيه زرار قبول أو اعتذار، وزرار **إضافة للتقويم**. الزرار بيعمل ملف `.ics` يشتغل مع iPhone وأندرويد وOutlook، ومعاه رابط Google Calendar.
- تذكير قبل الاجتماع، وإشعار لو الاجتماع اتأجل أو اتلغى.
- **اختياري:** محضر الاجتماع، وتحويل أي قرار لمهمة.

### 5.4 الأخبار والقرارات (المرحلة 1)
- النوع: خبر أو قرار. الجمهور: الشركة كلها، أو وحدات محددة. الإعلان ممكن يتثبت.
- اللي يقدر ينشر: كل دور عنده صلاحية `announcements.publish`، والنطاق بيحدد مين يقدر يوصله الإعلان.
- **التسليم:** إشعار، وقائمة "الأخبار والقرارات" في التطبيق، ومعاها حالة "اتقرا".

### 5.5 العقود والإقامات (المرحلة 2)
- **انتهاء العقد:** من `contract_end`.
- **انتهاء الإقامة:** من `iqama_expiry`.
- **مهلة المستقدم:** تاريخ الدخول + مدة السماح. الافتراضي 90 يوم، والشركة تقدر تغيّره.
- **مدة التنبيه:** تحددها الشركة، والافتراضي 30 يوم.
- **وظيفة يومية مجدولة** بتبعت تنبيه للـHR ولمدير الحساب: "موظف X لسه ما طلعتلوش إقامة"، أو "إقامة X هتخلص في تاريخ معين"، أو "عقد X هيخلص في تاريخ معين".
- لما الموظف يسجل إقامته، نوع الهوية بيتحول من "رقم حدود" لـ"إقامة".

### 5.6 الإجازات والرواتب والسلف (المرحلة 4)
- **الإجازات:** أنواع ورصيد لكل موظف، والطلب بيمر على محرك الطلبات.
- **الرواتب:** الراتب الأساسي والبدلات، وخصومات الحضور تتطبق تلقائيًا، وكشف راتب شهري.
- **السلفة:** طلب بيمر على محرك الطلبات، والمسؤول يقدر يوافق أو يرفض أو يأجّل أو يحوّل للمالية. ممكن تتخصم بأقساط من الراتب.

### 5.7 تذاكر الدعم (المرحلة 3)
- أي مستخدم في شركة مشتركة يفتح تذكرة لصاحب المنصة: نوعها، ووصفها، ومرفقات.
- **الحالات:** مفتوحة، وجاري المعالجة، ومستنية رد العميل، ومحلولة، ومقفولة.
- فيه محادثة داخل التذكرة، وإشعارات بكل تحديث.

## 6. نموذج البيانات (المرحلة 1)

كل الجداول الخاصة بالشركات فيها عمود `company_id`، وعليها سياسة RLS بتسمح بالوصول لأعضاء نفس الشركة بس، وكمان حسب نطاق الصلاحية.

| الجدول | أهم الأعمدة |
|---|---|
| `platform_admins` | `user_id` |
| `plans` | `name`, `price_monthly`, `price_yearly`, `max_employees`, `modules[]`, `is_active` |
| `department_catalog` | `name_ar`, `name_en`, `is_fixed` |
| `companies` | `legal_name`, `cr_number` (unique), `employee_count`, `activity_type`, `status` |
| `subscriptions` | `company_id`, `plan_id`, `status`, `starts_at`, `ends_at` |
| `org_units` | `company_id`, `parent_id`, `type`, `name`, `catalog_id`, `is_fixed`, `manager_position_id` |
| `roles` | `company_id`, `name`, `system_key` |
| `role_permissions` | `role_id`, `permission`, `scope` |
| `positions` | `company_id`, `org_unit_id`, `title`, `role_id`, `is_manager` |
| `employees` | `company_id`, `user_id`, `position_id`, بيانات القسم 4.2, `status` |
| `invitations` | `company_id`, `position_id`, `token_hash`, `sent_to`, `expires_at`, `used_at`, `created_by` |
| `announcements` | `company_id`, `kind`, `title`, `body`, `audience_unit_ids[]`, `pinned`, `published_by` |
| `announcement_reads` | `announcement_id`, `employee_id`, `read_at` |
| `notifications` | `user_id`, `type`, `payload`, `read_at` |
| `audit_log` | `company_id`, `actor_id`, `action`, `entity`, `before`, `after`, `at` |

## 7. الأمان والخصوصية

- **العزل بين الشركات:** سياسات RLS على كل جدول، ومعاها اختبارات آلية بتتأكد إن مستخدم من شركة مش قادر يقرا بيانات شركة تانية.
- **أرقام الهوية والإقامة والحدود:** مشفرة في قاعدة البيانات (pgcrypto/Vault)، ومش بتظهر كاملة غير لدور الـHR ولمدير الحساب.
- **الامتثال لنظام حماية البيانات الشخصية السعودي (PDPL):** إقرار موافقة وقت التسجيل، وسجل تدقيق لكل تعديل على بيانات حساسة، وتخزين البيانات في منطقة قريبة.
- **روابط الدعوة:** بيتخزن منها الـhash بس، وبتستخدم مرة واحدة ولها مدة انتهاء.
- **سجل التدقيق:** لكل عمليات التعيين والفسخ وتغيير الصلاحيات وحذف الوحدات.

---

## 8. التعامل مع الأخطاء

- **رسائل واضحة بالعربي** للحالات المتوقعة: رابط دعوة منتهي أو مستخدم، أو سجل تجاري مسجل قبل كده، أو محاولة حذف وحدة عليها موظفين، أو تجاوز الحد الأقصى لموظفين الباقة.
- **العمليات المركبة** بتتنفذ في معاملة واحدة (transaction) في قاعدة البيانات، وبتتنفذ كلها أو متتنفذش خالص. أمثلة: نقل موظفين وحذف وحدة، أو قبول دعوة وإنشاء موظف.
- **انتهاء الاشتراك:** الشركة تقدر تقرا بياناتها بس ومتقدرش تعدّل، ومعاها تنبيه بالتجديد. البيانات مبتتمسحش.

---

## 9. الاختبار

- **اختبارات وحدة** لمنطق الشغل المشترك: حساب المدير المباشر، وفحص الصلاحيات والنطاقات، وقواعد حذف الوحدات، وحساب مهلة الإقامة.
- **اختبارات قاعدة البيانات** لسياسات RLS: عزل الشركات، ونطاقات الأدوار.
- **اختبارات من البداية للنهاية (E2E)** للرحلات الأساسية: تسجيل شركة، وبناء الهيكل، ودعوة موظف، وتسجيله، ونشر خبر، ووصول الإشعار.

## 10. المراحل

| المرحلة | المحتوى | المنصات |
|---|---|---|
| **1 (الأساس)** | لوحة صاحب المنصة، الباقات والاشتراكات (من غير بوابة دفع)، تسجيل الشركات، الهيكل والفروع، المناصب والصلاحيات، الدعوات وتسجيل الموظفين، الأخبار والقرارات، الإشعارات | ويب + موبايل |
| **2** | الحضور والانصراف والخصومات، محرك الطلبات والأعذار، العقود والإقامات وتنبيهاتها | + ديسكتوب (أجهزة البصمة) |
| **3** | المهام، الاجتماعات، تذاكر الدعم | الكل |
| **4** | الإجازات، الرواتب، السلف، بوابة الدفع للاشتراكات | الكل |

كل مرحلة ليها خطة تنفيذ مستقلة، وبتتسلم شغالة قبل ما المرحلة اللي بعدها تبدأ.

## 11. افتراضات محتاجة تأكيد

1. **طريقة تسجيل الحضور:** GPS وQR من الموبايل، والشركة تختار. الربط مع أجهزة البصمة من الديسكتوب في المرحلة 2.
2. **الديسكتوب:** نفس تطبيق الويب ملفوف كبرنامج، ويتبني في المرحلة 2 علشان أجهزة البصمة.
3. **التذاكر:** من الشركات لصاحب المنصة. التذاكر الداخلية جوه الشركة مش داخلة دلوقتي.
4. **الموظف يتبع شركة واحدة ومنصب واحد** في المرحلة 1.
5. **الدفع:** في المرحلة 1 الاشتراكات بتتفعل يدويًا من لوحة صاحب المنصة، وبوابة الدفع (زي Moyasar أو Tap) في المرحلة 4.
6. **الأدوار والصلاحيات:** الشركة تقدر تعدّل فيها وتضيف أدوار جديدة.
7. **اللغات:** العربي أساسي والإنجليزي ثانوي.
